# Breakpointer — Product & Delivery Plan

> **Version:** 0.5.0 · **Status:** V1, the v0.2 inspection toolkit, the v0.3 redesign and pro toolkit, the v0.4 find, audit and verify release and the v0.5 whole-site and sharing release, built and tested; **live on the Chrome Web Store** since 0.4.0 (17 Oct 2026); 0.5.0 ready to upload as an update
> **Source:** refines the original planning brief (`plan.md`) into a delivery plan with decisions, status and acceptance criteria.

**Product goal:** help people check how a website looks at several viewport sizes, side by side, directly in Chrome — reliably, with minimal permissions, and honest about limits.

**Principle:** start with a reliable responsive preview workflow, then grow into a broader responsive testing toolkit.

## 3. Scope — what V1 delivers

### P0 (required for the first usable release) — all done

- [x] Open Breakpointer from the Chrome toolbar (popup, `Alt+Shift+V`).
- [x] Preview a typed URL or the current tab's URL (popup "Preview this page", context menu, `Alt+Shift+P`, address-bar keyword `bpt`).
- [x] Multiple viewport previews in one workspace (wrap or single-row layout).
- [x] Presets for mobile, tablet, laptop and desktop (15 sizes, named by size class — no device-emulation claims).
- [x] Custom viewport by width × height, validated (200–3840 px).
- [x] Portrait/landscape toggle per viewport.
- [x] Reload one preview, or all.
- [x] Remove a viewport (with undo) and add another.
- [x] Zoom per viewport, zoom all, and **Fit** (largest common zoom that fits the screen).
- [x] Layout and preferences saved in `chrome.storage.local`, validated on read.
- [x] Clear errors: invalid URL, unsupported scheme, unreachable host, likely embedding block.
- [x] Fallback to open a blocked site in a normal tab (plus exact-size window).

### P1 — delivered in V1

- [x] Rename and reorder viewports (card menu, drag-and-drop chips, `Alt+←/→` on chips).
- [x] Saved viewport groups (save/rename/update/delete) + 6 built-in groups (Responsive basics, Mobile QA, Tablets, Laptop & desktop, Tailwind and Bootstrap breakpoints).
- [x] Keyboard shortcuts (workspace single-key shortcuts + Chrome commands) and a help dialog.
- [x] Dark, light and system themes.
- [x] Screenshot export (one preview, or the visible workspace) — permission explained first.
- [x] Keyboard accessibility, visible focus, axe WCAG 2.1 AA checks in both themes; popup tuned for its small size.

### Extras added to make V1 complete

- [x] Show/hide viewports without losing them (hidden previews don't load).
- [x] Breakpoint labels for Tailwind and Bootstrap; pixel rulers.
- [x] Duplicate viewport; undo for remove, group apply, import, reset, group delete.
- [x] Export/import settings as JSON (browsing data excluded) for backup or team sharing.
- [x] Opt-in "remember recent addresses" (off by default, local only).
- [x] Site access manager (see and revoke what was granted); blocked-site tips with "Don’t show again".
- [x] English and Vietnamese UI; Vietnamese store listing and promo images.
- [x] First-run welcome; first page load auto-fits to the screen.

### v0.2 — Inspection toolkit — delivered

- [x] **Synced scrolling** and **synced navigation** across previews (links, forms, single-page-app routes; in-page `#anchors` are ignored).
- [x] **Responsive checks** per preview: sideways overflow (with the outermost culprits), missing mobile viewport tag, text under 12 px, touch targets under 24×24 px — with highlight in the page.
- [x] **Layout outlines** and **live CSS** applied to every preview at once (session only).
- [x] **Column grid** overlay (auto 4/8/12 or fixed columns, gutter, margin).
- [x] **Custom breakpoints** (editable list) and **Test breakpoint edges** (viewports on both sides of each breakpoint, fitted, with undo).
- [x] **Rotate all**; **Ctrl/⌘ + wheel** zoom; **Space + drag** pan.
- [x] **Saved pages** (star in the address bar, suggested first, managed in Settings, included in exports).
- [x] **HTML report** with a screenshot and the checks of every visible viewport.
- [x] More presets: compact phone, foldables (folded/open), 11″ pro tablet, 14″ laptop, ultrawide, 4K.

### v0.3 — Redesign and pro toolkit — delivered

- [x] **New design system** (colours, depth, motion, type in both themes), redesigned workspace, cards, dialogs, popup and welcome page; floating zoom dock; styled selects; tooltips with shortcuts; two-pane Settings.
- [x] **Command palette** (`Ctrl/⌘ + K`): actions, presets, groups, pages and settings; preview a typed address; accent-insensitive search.
- [x] **Drag to resize** with breakpoint snapping, guides and keyboard support; **focus mode**; **back/forward** between previewed pages; **address suggestions**.
- [x] **Inspector**: pick an element in one preview, compare it at every size, see what changes.
- [x] **This site's breakpoints** (from its media queries) for labels, snapping, edges and custom breakpoints.
- [x] **Page colours per viewport** (light/dark styles via `prefers-color-scheme`).
- [x] **All viewports in one image**, **copy screenshot**, **hide scrollbars**, **sort by width**, **scroll all to top**; synced scrolling by content.
- [x] **Compare two addresses** (A/B): a B preview for every viewport — the same page on another site, following A (and leading it), or a fixed address; swap, change, stop.
- [x] **Simulate** menu: colour vision deficiencies and blurred vision (every site); prefer reduced motion and pause animations; layout stress tests — pseudo-translated longer text and right to left (sites you allow).
- [x] **Measure** (`X`), **colour contrast checker** with eyedropper (`C`), **design overlay** with opacity and difference blend.
- [x] **Real windows** of each viewport, a **floating** always-on-top preview, a **side panel**, **full-page screenshots**; text spacing, prefers-contrast and print styles; image-size and tab-order labels; a baseline grid.
- [x] Checks for **upscaled (blurry) images** and **fixed elements covering the screen**; **saved live CSS snippets**; inspector **Copy table** (Markdown); `[` `]` `0` `O` shortcuts; scroll all to bottom; copy the page address.

### v0.4 — Find, audit and verify — delivered

- [x] **Scan every width** (`W`): exact ranges of every issue (coarse pass + bisection to 1 px), page height, site breakpoints and viewports on one chart; slider and pointer read-out; jump to the worst width; add a viewport there; copy as Markdown; included in reports.
- [x] **Audit panel** (`E`): issues of every preview grouped by check with per-preview highlights; page weight, requests, image pixels vs. screen needs, LCP, CLS, page height, elements and fonts as bars; type scale of headings, text, links, buttons and fields; Markdown for each tab; a count of issue kinds on the toolbar.
- [x] **Visual check** (`V`): baselines per page × viewport in IndexedDB, comparisons with changed share and regions, side-by-side / slider / differences views, accept, delete per page or all from Settings.
- [x] **New checks**: text cut off by its box, low-contrast text (modern colour spaces), layout shifts; each check can be switched off.
- [x] **Inspector**: margin and padding on hover; capture the element at every size at a common scale; the comparison in reports.
- [x] **Grid & flex layouts** overlay; **page colours of every preview** at once; `1`–`8` focus a viewport; six presets (28 in all).
- [x] **Reloads keep the scroll position**; **automatic reloads**; **workspace links**; **access until Chrome closes**; what's new after an update; page stats in reports.

### v0.5 — Whole site and sharing — delivered

- [x] **Check pages** (`B`): a list of pages (typed, saved pages, the links on the page, the sitemap) checked at every visible viewport; a table of pages × sizes with each cell's issues; failures explained (HTTP status, site not allowed, timeout); open a page in the workspace; Markdown and an HTML report; allow every missing site in one prompt.
- [x] **Showcase image**: the page at up to four sizes in device, window or no frames, on four backdrops and three shapes, with a title and an optional credit; download or copy.
- [x] **Feedback & support** in Help (issue forms, rating or a GitHub star, share link); a one-time rating question for store installs; reports and Chrome's "Visit website" link to Breakpointer's home.
- [x] Dependencies updated, Dependabot, GitHub issue forms; a landing page (`site/`, GitHub Pages) and a launch kit.

### Non-goals (unchanged)

No accounts or cloud, no AI, no collaboration, no hosted dashboard, no promise that every site embeds, no claim of real-device emulation.

## 4. Permissions and privacy

| Permission                            | When                     | Install warning              | Why                                                                                                                             |
| ------------------------------------- | ------------------------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `storage`                             | Install                  | None                         | Save viewports, groups and preferences locally                                                                                  |
| `activeTab`                           | Install                  | None                         | Read the current tab's URL only when the user invokes Breakpointer                                                              |
| `contextMenus`                        | Install                  | None                         | "Preview in Breakpointer" on pages and links                                                                                    |
| `declarativeNetRequestWithHostAccess` | Install                  | None                         | Let previews of **allowed** sites ignore frame-blocking headers and Fetch Metadata frame checks, in the viewer tab only         |
| `sidePanel`                           | Install                  | None                         | Preview the page you're browsing in Chrome's side panel                                                                         |
| `scripting`                           | Install                  | None                         | Register the frame agent while a workspace is open; it only runs where host access was granted, and only acts in preview frames |
| Host access (`<all_urls>` subset)     | **Optional**, at runtime | Chrome prompt when requested | Per site: show blocked sites. All sites: also enables screenshots                                                               |

No data leaves the browser. v0.4 adds no permission: visual baselines use the extension's IndexedDB, and "until Chrome closes" uses the same optional host permission, removed by the service worker at the next start. v0.5 adds no permission either: Check pages uses the optional host access (several sites can be allowed in one prompt), sitemaps are read with that access, and `chrome.management.getSelf` (to link to the right store) needs none. Details: [PRIVACY.md](PRIVACY.md). Store justifications: [STORE_LISTING.md](STORE_LISTING.md).

## 6. Release plan (M3 → store)

Breakpointer is public on the Chrome Web Store as **Breakpointer — Responsive Viewport Tester** (id `naoadcallefanlcneemohjepkficejjh`, publisher Tanix): https://chromewebstore.google.com/detail/naoadcallefanlcneemohjepkficejjh. Version 0.4.0 went live on 17 Oct 2026. Each release is an update of that item:

1. `npm run package` → `release/breakpointer-<version>.zip`; load it unpacked in a **clean Chrome profile** and run the manual checklist in [TESTING.md](TESTING.md).
2. Developer Dashboard → the item → Package → upload the zip.
3. Listing: refresh from [STORE_LISTING.md](STORE_LISTING.md) (EN + VI) when it changed — for 0.5.0 the new summary and the five screenshots in its order (workspace, Check pages, scan, showcase, audit), promo tiles `brand/store/promo-*.png`, and the demo video once it is on YouTube.
4. Privacy tab: update the permission justifications if they changed (0.5.0: Check pages in the `scripting` and host-access texts).
5. Submit for review; updates of an item usually pass faster than a first review.

**Name:** another, older extension on the store is also called “Breakpointer” (a Bootstrap breakpoint box by 8sidewaysmonkeys.com) and can appear first when people search for the bare name. Always link to the listing directly (with UTM parameters, which the store keeps through its redirect) and use the full name in posts.

**Owner decisions still needed:** a license (the repository is public but has no license yet, so all rights are reserved).

**Links for the store:** listing https://chromewebstore.google.com/detail/naoadcallefanlcneemohjepkficejjh · privacy policy https://github.com/Tanx-1811/breakpointer/blob/main/docs/PRIVACY.md · support https://github.com/Tanx-1811/breakpointer/issues · homepage https://github.com/Tanx-1811/breakpointer

## 7. Risks and mitigations

| Risk                               | Mitigation in V1                                                                                                                    | Next step                                                                     |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Many sites block framing           | Opt-in site access, clear notice, new-tab and exact-size-window fallbacks                                                           | Track "blocked" rate in feedback (M4)                                         |
| Users distrust "all sites" access  | Never requested at install; per-site option first; explained before Chrome's prompt; revocable in-app; "until Chrome closes" (v0.4) | Track how often people choose it (M4)                                         |
| Preview differs from a real device | Copy says "viewport", not "device"; help dialog lists what isn't emulated                                                           | V2 could add optional UA header per workspace                                 |
| Performance with many previews     | Max 8 viewports; hidden previews don't load at all                                                                                  | Measure memory on low-end machines; consider lazy-loading off-screen previews |
| Looks like existing tools          | Fast workflow, saved groups, breakpoint labels, honest errors, bilingual UI                                                         | Validate differentiators with testers                                         |
| Scope creep                        | V2–V4 kept as ideas behind feedback                                                                                                 | Re-prioritise after M4                                                        |

## 8. Milestone 4 — feedback and iteration

**Goal:** learn what to build next from real use, without invasive analytics.

| Task                                                                 | Acceptance criteria                                                                            |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Recruit 5–10 testers (devs, designers, QA, agency)                   | Each uses it on ≥ 3 of their own sites over a week                                             |
| Add an in-app "Send feedback" link (mailto or GitHub issue template) | ✅ v0.5: Help → Feedback & support, GitHub issue forms; nothing collected automatically        |
| Short survey                                                         | Questions: blocked-site rate, most used presets/groups, missing features, trust in permissions |
| Triage                                                               | Rank requests by frequency × effort; update this plan                                          |

Success signals (only from opt-in feedback): successful preview starts, how often sites are blocked, time to set up a workspace, 7/30-day return use, use of saved groups.

## 9. Roadmap (ideas, ordered by expected value)

**Delivered in v0.2:** synchronized scrolling and navigation, custom breakpoints, overflow and other responsive checks, a simple report. **Delivered in v0.3:** the responsive inspector (an element compared at every size), the page's own breakpoints, drag to resize, page colours, the command palette and the redesign; comparing two addresses, remembered live CSS snippets, a measuring tool, simulations and stress tests. **Delivered in v0.4:** the width scanner, the audit panel, visual baselines with diffs (the first step of V3), three new checks, access until Chrome closes, the inspector's comparison in reports, reloads that keep the place (see §3).

**Delivered in v0.5:** Check pages (a list of pages at every viewport, from saved pages, links or the sitemap), showcase images, feedback, rating and sharing in the product.

**v0.6 — polish from feedback**

- Per-group breakpoint sets.
- Save the design overlay, the comparison and the scan range with a group.
- Check pages: a screenshot per page and size, and comparison with visual baselines (the first step of V3 across pages); CSV export.
- More languages if requested (the store listing first: Spanish, Portuguese, Japanese, German, French, Indonesian).

**V2 — Deeper inspection**

- Container-query and height breakpoints (the scanner could sweep heights too); measure the distance between two elements picked in the inspector (the measuring tool covers areas drawn by hand).
- Inspector: follow the element while navigating.

**V3 — Visual regression**

- Full-page baselines; repeatable runs over saved pages × groups; a report of what changed (v0.4 delivered baselines of what is on screen, with diffs and regions).

**V4 — Broader toolkit**

- Optional projects and sync, team sharing, CI integration — only if validated.

## 10. Definition of done (per change)

- Lint, format, typecheck, unit and e2e tests pass in CI.
- New UI strings exist in English and Vietnamese.
- Keyboard accessible with visible focus; axe passes.
- No new permission without a written justification in this plan and the store listing.
- Docs updated (README, PLAN, ARCHITECTURE as relevant) and a CHANGELOG entry added.
