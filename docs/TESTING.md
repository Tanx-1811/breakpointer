# Testing

## Automated

```sh
npm test            # unit tests (Vitest, jsdom)
npm run test:e2e    # builds dist + dist-e2e, then Playwright end-to-end and accessibility tests
npm run screenshots # regenerates store screenshots from the real UI (brand/store/screenshots)
npm run demo-video  # records brand/social/demo.mp4 and demo.gif from the real UI (needs ffmpeg)
```

The end-to-end suite loads the real extension into **Chrome for Testing**, Google's Chrome build for automation that Playwright bundles (156 at the time of writing). Branded Google Chrome (137 and later) no longer loads extensions from the command line, so testing in your everyday Chrome is manual: `chrome://extensions` → Developer mode → Load unpacked → `dist/`.

- **with-access** (`dist-e2e`): host access is granted in the manifest, as if the user allowed all sites, because automated tests can't click Chrome's permission prompt. Covers real viewport widths, blocked sites, frame-busting, workspace editing, groups, persistence, settings, screenshots, popup, axe checks the v0.2 tools (`tools.spec.ts`: synced scrolling and navigation, checks and highlights, outlines, live CSS, grid, custom breakpoints, edges, rotate all, saved pages, report, wheel zoom and pan) and the v0.3 features (`features.spec.ts`: command palette, back/forward, address suggestions, drag and keyboard resizing with snapping, focus mode, site breakpoints, inspector, page colours, hidden scrollbars, the all-in-one image and copying, sorting) and the utilities (`utilities.spec.ts`: comparing two addresses, vision simulations, measuring, the contrast checker, stress tests, reduced motion and paused animations, the image and fixed-cover checks, design overlays, CSS snippets and the new shortcuts, with axe checks of the new menus and dialogs in both themes) and the v0.4 tools (`audit.spec.ts`: the new checks — and what they must not flag — switching checks off, the audit panel's three tabs and Markdown; `scan.spec.ts`: the width scanner's exact ranges, site breakpoints, the slider and adding a viewport; `visual.spec.ts`: baselines, comparisons, the three views, accepting, and baselines in Settings; `inspector-plus.spec.ts`: capturing an element at every size, grid and flex labels; `workspace-plus.spec.ts`: reloads that keep the scroll position, automatic reloads, 1–8, workspace links, page colours for every preview, what's new; `a11y-plus.spec.ts`: axe on all of them in both themes) and the v0.5 tools (`batch-showcase.spec.ts`: Check pages with links worth checking, the sitemap named in robots.txt, a 404, issues per size, Markdown, the report and opening a page; the showcase image's options and its PNG; Help's feedback links; `a11y-plus.spec.ts`: axe on Check pages, the showcase image and Help in both themes).
- **no-access** (`dist`): the production build exactly as installed — checks the embedding notice, that blocked sites stay blocked, that screenshots explain the permission first, that in-frame tools offer to allow the site and run nothing without access, that vision simulations and measuring work without access (`utilities-no-access.spec.ts`), that Check pages names the sites it may not check and marks their pages at once (`batch-no-access.spec.ts`), and that the manifest requests no host access.

Run headed with `HEADED=1 npx playwright test`.

## Release checklist

- [ ] `npm run lint && npm run format:check && npm run typecheck && npm test && npm run test:e2e` pass.
- [ ] `npm run package`; load the zip's contents unpacked in a clean profile; matrix above passes.
- [ ] `chrome://extensions` shows no errors; the install dialog shows **no** permission warnings.
- [ ] Permissions in the store listing match `src/manifest.ts`; privacy policy is up to date.
- [ ] No debug logging (only `console.warn` on failures).
- [ ] Version bumped in `package.json`; CHANGELOG updated; screenshots regenerated if the UI changed.
- [ ] Breakpointer Pro: `PRO_CHECKOUT_URL` points to the live checkout (or the release is packaged with `--allow-no-checkout` on purpose); a key issued with the production signing key activates in the packaged build; `npm run package` didn't refuse the build ([PRO.md](PRO.md)).
