How it works

From any page to every size in seconds

  1. Preview this page

    Open any page

    Click the Breakpointer button and choose Preview this page — or press Alt+Shift+P, right-click a link, or type bpt in the address bar. Your local dev server works too.

  2. 390 × 844768 × 10241440 × 900

    See every size at once

    Up to 8 previews side by side, from 28 presets or your own sizes. Each has a real layout width and height, so media queries, container queries and innerWidth respond as in a window that size.

  3. WEVB

    Let it find what breaks

    Allow the site once, and every preview is checked as you browse. Press W to scan every width, E to audit, V to compare with a baseline and B to check a whole list of pages.

Features

Don’t just look at sizes. Find what breaks.

Breakpointer checks every preview for you and pins each problem to the width where it happens — so you can fix it before anyone else sees it.

Scan every width W

The page is checked at every width of a range — 320 to 1440 px, say — and each issue’s first and last width is found to the pixel. One chart lines up the issues with the page’s height, this site’s breakpoints and your viewports.

  • A pass every 8, 16 or 32 px, then narrowed to the pixel
  • See the page at any width with the slider
  • Jump to the worst width and add a viewport there in one click

Audit every size E

Every issue of every preview, grouped by check, with a highlight in the page. Page weight, requests, image pixels, LCP and layout shift as bars per size — and the type scale of headings, text and buttons at every width.

  • The selector of each element at fault
  • Performance and type compared per viewport
  • Copy any table as Markdown for a ticket or a pull request

Visual check V

Save a baseline of every viewport, then compare after a deploy, a CSS change or against staging. See what changed, pixel by pixel — side by side, with a slider, or with the differences boxed.

  • How much of the image changed, and where
  • Accept a capture as the new baseline
  • Baselines stay in your browser, never uploaded

Check pages B New

Check a whole list of pages at every viewport in one run — your saved pages, the links on a page, or the site’s sitemap. A table shows which pages break, and at which sizes.

  • Fill the list from a page’s links, the sitemap or your saved pages
  • Open any page from the results
  • Copy the table as Markdown or download an HTML report

Inspector I

Click an element in one preview and compare it at every size: box size, display, font, spacing and flex or grid layout. What changes between sizes is highlighted.

Showcase image New

Your page at several sizes in simple device frames or browser windows on a backdrop — ready for a portfolio, a client or a post. Download a crisp PNG or copy it. The frames are decorative.

And the rest of the toolkit

Everything else you reach for while making a layout work at every size.

  • Responsive checks Sideways overflow and its culprit, a missing viewport tag, tiny text, small touch targets, text cut off, low-contrast text, blurry images, fixed elements covering the screen and layout shifts.
  • This site’s breakpoints Read from the page’s own CSS — or use Tailwind, Bootstrap or your own — to label previews and test both sides of each.
  • Drag to resize Pull an edge and watch the page reflow live. Edges snap to breakpoints, with guides and a size read-out.
  • Light and dark side by side Show any preview with the page’s light or dark styles, whatever your system prefers.

  • Simulate Colour-vision deficiencies, blurred vision, reduced motion, pseudo-translated text about 40% longer, and right-to-left.
  • Measure and match Measure in CSS pixels, check contrast with an eyedropper, and lay a design mockup over a preview.

  • Screenshots and reports One preview, all viewports in one labelled image, full-page captures and an HTML report of every size.
  • Groups, saved pages and links Save viewport groups, star the pages you test often, and share a workspace link.

Breakpointer and DevTools

How it differs from DevTools device mode

Device mode shows one viewport at a time and leaves the looking to you. Breakpointer shows all your sizes at once — and does the looking.

What you need DevTools device mode Breakpointer

Need a device’s user agent, pixel density or touch events? That’s a job for DevTools. Breakpointer changes the viewport only — the two work well together.

Privacy

Private by design

No account, no analytics, no server. Nothing you preview, measure or capture leaves your browser.

Read the privacy policy

  • It stays on your device

    Settings live in Chrome’s local storage. Baselines, screenshots and reports are made in your browser and never uploaded.

  • No site access at install

    Breakpointer asks only when you need it — for one site, all sites, or just until Chrome closes. Remove access anytime.

  • Why it asks

    Some sites refuse to be shown in frames, and the in-page tools — checks, scan, audit, inspector — run a small packaged script inside previews of the sites you allowed.

  • Screenshots

    Chrome lets an extension capture a tab only with access to all sites, so your first screenshot asks for it.

FAQ

Questions, answered

Something else? Ask on GitHub.

Is Breakpointer free?

Yes. It’s free and needs no account or sign-up. The code is public on GitHub, where you can report a bug or suggest a feature.

Does it emulate devices?

No. Each preview gets a real layout viewport — media queries, container queries and window.innerWidth respond as they would in a window that size — but the user agent, pixel density, touch input and browser engine stay those of your Chrome. Use DevTools device mode or a real phone for those.

Sign-in state and third-party cookies can also behave differently inside previews.

Why doesn’t a site show up, and how do I allow it?

Many sites tell browsers not to show them inside other pages (with X-Frame-Options or a CSP frame-ancestors rule), so the preview stays blank or says “refused to connect”.

Click the Allow button that appears with the preview — for that site, all sites, or only until Chrome closes — and it loads. Allowing a site also turns on the in-page tools for it. You can also open the page in a new tab or in a window of the exact size.

Which browsers does it work in?

Chrome 116 or later on the desktop. Other Chromium-based browsers that install extensions from the Chrome Web Store, such as Edge or Brave, may work, but they aren’t officially tested.

Does anything leave my browser?

No. There’s no account, analytics or server: settings, baselines and screenshots stay on your device. The pages you preview load like any page in Chrome, straight from their own sites.

Does it work with localhost?

Yes. Type localhost:5173 — or any port, *.localhost name or IP address — to preview your dev server. Allow it once to use the checks and tools on it.
